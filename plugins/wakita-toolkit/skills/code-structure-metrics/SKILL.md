# 代码结构量化审查

把「感觉乱」变成可指认、可量化的信号。每条结论必须带具体文件和数字，禁止只写「结构较乱」。

## 默认阈值

以下是默认参考值；项目 `AGENTS.md` 或 lint 配置有明确阈值时，以项目为准。

| 指标 | 默认阈值 | 说明 |
|---|---|---|
| 单文件行数 | > 400 行 | 超过先看职责数，不只看行数 |
| 单函数行数 | > 50 行 | 超过通常意味着多职责 |
| 单组件行数 | > 200 行 | template + script + style 合计 |
| 嵌套层数 | > 3 层 | if/for/try 嵌套 |
| 单文件导出数 | > 10 个 | 公共 API 过宽 |
| 重复代码块 | 3+ 处相同或近似 | 与 `code-reuse-audit` 联动 |
| 循环依赖 | 任意一处 | 直接判结构问题 |

## 信号清单

### E1 硬编码

| 类型 | 判定 | 级别建议 |
|---|---|---|
| 密钥/令牌/连接串 | 代码、日志、前端变量、注释里出现 | P0 |
| 环境相关配置 | URL/域名/端口/超时/阈值/开关直接写在逻辑里 | P1 |
| 文案/提示语 | 用户可见文案散落在组件里，未集中管理 | P1 |
| 颜色/尺寸/字号/间距 | 未走 CSS 令牌或主题变量 | P1 |
| 令牌引用未定义 | `var(--x)` 在 tokens/theme 里找不到 `--x:`；无 fallback → 整条声明失效（P0），有 fallback → 掩盖缺失（P1） | P0/P1 |
| 魔法数字 | 业务含义靠注释或猜测 | P2（核心逻辑可升 P1） |

> 令牌引用完整性、UI 库主题桥接、断点阶梯/大屏策略、跨 app 令牌对齐，统一由 `frontend-design-system-audit` 深查；本 skill 只负责在 E1 里标记并路由。

### E3 超长

- 单文件、单函数、单组件超过默认阈值。
- 单文件导出过多，调用方难以判断该用哪个。
- 严重超标（数千行/多职责混杂）→ P0；一般超标 → P1。

### E5 理解困难

- 命名不达意：`data`、`temp`、`handle`、`process` 看不出业务含义。
- 一个函数做多件事：校验 + 转换 + 持久化 + 通知混在一起。
- 隐式副作用：读起来像查询，实际写库/发消息/改全局状态。
- 依赖不显式：靠全局变量、模块级单例、隐式上下文传参。
- 控制流深嵌套，或大段魔数没有解释。
- 一个文件混多种关注点（路由 + 业务 + SQL + 模板）。
- 核心模块 → P1，边缘 → P2。

### E7 耦合异常

- 循环依赖（A import B，B import A）。
- 模块间直接 import 对方内部文件，绕过公开入口。
- 全局可变状态被多处读写。
- 改一处需要同步改多处，且没有编译/测试能兜住。
- 循环依赖 → P1；核心链路耦合 → P0/P1。

## 怎么量

按项目技术栈选命令，优先用现成工具，不要手数。

```bash
# 文件行数 Top 20
find <范围> -type f \( -name '*.py' -o -name '*.ts' -o -name '*.vue' -o -name '*.js' \) \
  -not -path '*/node_modules/*' -not -path '*/.venv/*' -exec wc -l {} + | sort -rn | head -20

# 函数/类定义位置（用于估算函数长度）
grep -rnE "^(export )?(async )?(function|def|class) " <范围>

# JS/TS 循环依赖
npx madge --circular --extensions ts,tsx,js,jsx,vue <入口或目录>

# Python 依赖图（可选）
pydeps <包名> --show-deps
```

Vue 单文件组件按 `<template>/<script>/<style>` 分段估算；不要把整文件行数直接当组件逻辑行数。

## 输出

1. **混乱地图**：问题最密集的目录/文件 Top 5，附量化数据（行数、职责数、跨层调用数、重复块数）。
2. **每个信号至少一条证据**：`文件:行` / 函数名 / 数字。
3. **清理成本量级**：小（单文件内改）/ 中（跨 2-3 文件）/ 大（跨模块或需改接口）。
4. **一句话判断**：乱在「文件太长」还是「职责混杂」还是「耦合太深」。

## 边界

- 重复代码、多套实现、未复用 → `code-reuse-audit`。
- 分层违规（UI 直接调 API/拼 SQL、跨层 import）→ `robust-architecture`。
- 契约漂移 → `robust-architecture`；安全硬编码（密钥）→ `project-compliance-check`。
- 本 skill 只给结构信号和量化证据，不直接改代码；重构方案由用户确认后另起流程。
